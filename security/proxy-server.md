# Proxy Server

## 概要

クライアントとサーバーの中間で両者の通信を中継する役割を担う。

プロキシサーバーには大きくフォワードプロキシとリバースプロキシがある。

それぞれの役割やメリットが異なるが、サイバー攻撃対策などが主な利点となってくる。

（以降、実際のコンテンツを持つ Web サーバーを「配信元サーバー（オリジンサーバー）」と呼称する。）

### フォワードプロキシ

Web クライアントからのリクエストを受け取り、 Web クライアントの代わりに配信元サーバーへのリクエストを送る。
受け取ったレスポンスを Web クライアントへ渡すことで、 Web クライアントからは自分が直接配信元サーバーと通信してるように見える。

代表的な例として Squid や企業・学校内のプロキシサーバーがある。

導入することで以下のようなメリットが有る

- 機関等の閲覧制限回避: 一部政府や学校などの組織はユーザーにアクセスできるサイトを制限しているが、プロキシに接続することでこれらの制限を回避する
- 特定コンテンツへのアクセスブロック: ↑とは逆にコンテンツフィルタリングルールを設定することで特定サイトなどのアクセスをブロックできる
- オンラインでの身元保護: 例えばフォワードプロキシを介してコメントをすると、コメント投稿に使用された IP アドレスはプロキシサーバーのものになるため、追跡が困難になる。
  - 例えば政治的にデリケートな話題を扱うなどリスクが伴う行動をする際に安全性が増す
- キャッシュによる高速化: 一度アクセスした Web コンテンツをプロキシサーバーにキャッシュすることで、同じコンテンツへの再アクセス時に高速化できる

### リバースプロキシ

Web システムの入口に設置され、 Web クライアントから受け取ったリクエストを配信元サーバーへ転送する。

配信元サーバーからのレスポンスを受け取ると、それをそのまま Web クライアントに返す。

フォワードプロキシがクライアントのプロキシなのに対して、リバースプロキシはサーバーのプロキシと言える。

代表的な例として CDN（Cloudflare、AWS CloudFront など）がある。

導入することで以下のようなメリットが有る

- 負荷分散: 所謂ロードバランサーはリバースプロキシの一種であり、これによって配信元サーバーへのトラフィックを均等化する
- 攻撃からの保護: 標的型攻撃の難易度が上がりセキュリティが向上
  - 配信元サーバーの IP アドレスを明らかにする必要がなく、配信元サーバー本体に直接リクエストが届かないようになるため
- グローバル負荷分散: Web サイトを世界中の複数サーバーに分散でき、リバースプロキシはクライアントからの通信を地理的に最も近い配信元サーバーに送信する
  - リクエストと応答の移動距離が短縮され、読込時間が減る
- キャッシング: リバースプロキシはコンテンツをキャッシュできる。↑と合わせて、配信元サーバーへのアクセス距離が遠くてもリバースプロキシサーバーからキャッシュされたコンテンツを取得することでパフォーマンスが向上する
- SSL 暗号化: 各クライアントの SSL/TLS 通信の暗号化、復号化は計算コストが高いため、配信元サーバーに代わりリバースプロキシで行うことで配信元サーバーの負荷を減らす
