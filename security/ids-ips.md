# IDS IPS

## 概要

ファイアウォールで防ぎきれない攻撃を防ぐ手段で、Intrusion Detection System, Intrusion Prevention System の略。

両者ともに通信監視をするネットワーク型と、サーバー上のユーザーの動きを監視するホスト型の2種類があるらしいが、参考資料に従いここでは前者のみ記載。

ネットワーク型ではネットワーク上で監視している通信の中で、不正アクセスと見られるものや、普段と異なる異常なものを検知している。

IDS は異常があったことをシステム管理者にメール等で通知し、 IPS はこれに加えて即座に該当する通信の遮断を行う。そのため、 IPS のほうが強固なセキュリティを実現出来る一方、誤検知に伴う可用性の低下が発生し得る。なので、システムの用途や性質に応じて使い分ける必要がある。

以下不正アクセスの検知方法について簡単に残す。

### シグネチャ（不正検知）型

シグネチャとは、既知の攻撃手法における通信パターンが登録された DB のこと。

これを用いて、監視対象の通信との比較を行い、 DB に登録されたパターンと一致する通信を不正アクセスと判断する。

DB に登録されているものから判断するため、全く新しい攻撃や既存攻撃が進化したといったケースでは、この検知方法を回避する可能性がある。

また、この特徴から DB の更新が重要となる。

### アノマリー（異常検知）型

普段の通信とは大きく異なる通信や、通常は発生しないような通信を不正アクセスと判断する。

この手法ではあらゆる異常動作に反応することから、シグネチャ型を回避する攻撃やゼロデイ攻撃も検知できる。

一方で誤検知が発生しやすく、許可されたユーザーが初めてアクセスした際などであってもトリガーされる可能性がある。

この手法では機械学習などを用いて、ベースラインモデルを作成後それを継続的に改良する。

### ポリシーベース型

セキュリティチームによって設定されたセキュリティポリシーに基づいて、ポリシーに違反したアクションを検出すると、そのアクションをブロックする。

例えば「特定のホストにアクセスできるユーザー」を規定するポリシーがある時に、権限を持たないユーザーがそのホストに接続しようとするとそれをブロックする。
