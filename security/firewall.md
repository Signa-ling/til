# Firewall

## 概要

ネットワークへの不正アクセスを防ぐシステム。
インターネットと内部ネットワーク間に配置し、送受信されるデータを監視してサービスに必要な通信だけを許可する。

大きく以下の種類がある

- パケットフィルタ型
- サーキットレベルゲートウェイ型
- アプリケーションゲートウェイ型
- 次世代ファイアウォール（NGFW）

### パケットフィルタ型

送受信されるデータ（パケット）の先頭にあるヘッダ情報に含まれる以下のような情報を解析して、通過させるかを判断する方式。

- 送信元の情報 ( IP アドレスやポート番号 )
- 宛先の情報 ( IP アドレスやポート番号 )

つまりネットワーク層〜トランスポート層の情報を元に判断している。

処理が高速で通信速度への影響が小さい利点がある一方、許可されたポートを使った攻撃などへの対応が難しい事が挙げられる。

この方式はスタティックな手法（予め設定した条件に基づいて許可等の判断を下す）と、ダイナミックな手法（宛先や送信元の情報をパケットの内容に応じて動的に変化させる）がある。

中でもパケットがどの TCP, UDP のセッションに属するものであるかを判断し、正当な手順の TCP/UDP セッションによるものだと判断出来る場合のみ許可する手法をステートフルインスペクションという。
この手法ではその判断方法から TCP/UDP セッションの一部情報を記憶する。（セッションの状態を記憶・追跡するため、状態テーブルを保持する）

イメージしづらかったので以下に例を載せる。

```text
[例: 外部からの不正なパケットをブロック]

1. 内部PC → 外部サーバー: SYN（接続要求）  → 状態テーブルに記録
2. 外部サーバー → 内部PC: SYN-ACK         → 記録済みセッションなので許可
3. 外部攻撃者 → 内部PC: ACK（いきなり）   → 対応するSYNがない → ブロック
```

### サーキットレベルゲートウェイ型

TCPなどのトランスポート層のプロトコルによるコネクションの確立プロセスを監視・制御する方式。所謂サーキットプロキシ。
例えば、クライアントとサーバー間で通信セッションが開始される際にこの方式の FW が代理でコネクションを確立し、セッションの正当性（許可されたポート番号や IP アドレスの組み合わせかなど）を判断し、その後実際のデータ通信を中継する。

プライベート IP アドレスしか持たない内部ネットワークからでも外部ネットワークへの接続が行えることがメリットである。

### アプリケーションゲートウェイ型

HTTP/HTTPS, FTPといったアプリケーション層のプロトコル通信を代理処理する。
一般的にこれをプロキシサーバーと称する。

データの内容まで検査する等、細かいセキュリティポリシーを適用したい場合に活用できるが、制御設定が難しかったり、処理負荷が高いことで通信速度に影響が出る可能性がある。

## 次世代ファイアウォール

次世代ファイアウォール（NGFW）は、従来のパケットフィルタリングに加え、IDS/IPS、マルウェア検知、アプリケーション識別などを統合したもの。
